# ST-ROTO v0 — trying it in Nuke (pre-alpha)

**Status: pre-alpha development build.** Several objects per node, Track forward from each prompt, Re-track in both directions; Nuke 17.1 on Windows with an NVIDIA GPU (CPU works but is slow). Tested on one synthetic shot. Nothing here is production-ready.

## Requirements on this machine

- Nuke 17.1 (Non-commercial works, within its limits: 1920×1080 max, 10 Python-accessible nodes per session)
- `D:\ST-ROTO` with the development set-up from this repository (`.tools\nuke-py311` packages, exported models in `models\onnx\`). Model weights are not in the repository; see `tools/models/`.

## Install with the setup (recommended)

Download the release files from GitHub (Releases): `ST-ROTO-Setup.exe`, `ST-ROTO-<version>.zip` (with the tiny model) and, if you want them, the model packages `ST-ROTO-model-sam2.1-hiera-large.zip` (more accurate, ~7 GB GPU memory) and `ST-ROTO-model-vitmatte-small-composition-1k.zip` (learned soft edges; see its licence note in NOTICE). Put them in one folder and double-click the .exe: choose 1 to install everything in the folder (every file is checked by SHA-256; a model package that does not belong to this version is refused; `ST-ROTO-Setup.exe install-model --source <model zip>` adds one later, and an upgrade keeps installed models the new version still uses) (no administrator rights; files go to `%LOCALAPPDATA%\ST-ROTO`, and one marked block is added to `%USERPROFILE%\.nuke\init.py`). The same menu repairs, rolls back to the previous version or uninstalls (which removes only ST-ROTO's block and files). Command line: `ST-ROTO-Setup.exe status | install --source <zip> | upgrade | rollback | repair | uninstall`. Windows may warn that the .exe is not signed.

## Enable the plugin manually (development checkout)

Option A, environment variable for your user: set `NUKE_PATH` to `D:\ST-ROTO\nuke_plugin` (append with `;` if it already has a value).
Option B: add this line to `%USERPROFILE%\.nuke\init.py` (create the file if needed):

```python
nuke.pluginAddPath("D:/ST-ROTO/nuke_plugin")
```

Restart Nuke. You should see **Nodes › ST-ROTO › ST_Roto** and the pane **ST-ROTO Objects** (Windows › Custom).

## Workflow

1. Save your script (the project file defaults to `<script>.stroto` next to it).
2. Select your Read node, then **Nodes › ST-ROTO › ST_Roto**. View the ST_Roto node.
3. Type an **object name** (e.g. `hero`). Go to the frame you want to prompt on, drag the **point** handle in the viewer onto the object and press **+ Include**. Add **− Exclude** points on things that must not be included. Each object's points must be on one frame.
   **Box (recommended for parts of something bigger, e.g. a sleeve, a bag, one person in a group):** drag the corners of the **box** rectangle in the viewer around the object and press **Set box**, then add include/exclude points if needed. Measured on real footage (51 tests, SA-V):

   | prompt | wrong object at the start | mean IoU over the shot |
   |---|---|---|
   | 1 click | 19 of 51 | 0.54 |
   | 3 clicks | 13 of 51 | 0.58 |
   | box only | 2 of 51 | 0.67 |
   | box + 1 click | 2 of 51 | 0.68 |

   A click alone is as good as a box when it picks the right object (check with **Preview**); the box mainly stops SAM choosing a different object or part. Recommended: a box plus one include click. **Clear box** removes only the box; **Clear points** removes the object's box and points.
   **From a rough mask:** draw a rough shape or polygon in the node's Roto, or use another node's alpha or a mask file: set *prompt from*, *source* (shape name / node name / file path, `####` = frame) and press **Use as prompt** on the frame; the box and a click are made from it and the AI draws the exact shape when you Track (measured: a rough square around an object -> IoU 0.985).
4. More objects: change **object name** (e.g. `car`) and add points for it, on any frame. The line under the points lists every prompted object. **Clear points** clears the named object, **Clear all** clears every object.
5. **Preview** shows the AI shape of the named object on its prompt frame (temporary).
6. **Load model** once per Nuke session (Nuke pauses for a few seconds once), then **Track**. All prompted objects are tracked in one pass (each frame is analysed once), forward from each object's prompt frame. The status line shows progress; **Cancel** stops it. The whole pass is **one undo step**. If you cancel, or Nuke crashes, **Resume track** continues where it stopped (same result as an uninterrupted run). Objects already tracked are skipped (status says so): use Re-track for them.
7. *points* (default auto) sets how many points each shape has; auto picks the fewest that follow the outline. Measured on real footage, auto loses less than 0.003 IoU against the AI's own mask, and 48 or 64 points add almost nothing, so keep auto unless you need more points to edit. *model* **auto (by free GPU memory)** uses the large model when it fits in the GPU memory free now (it needs ~7.1 GB, the tiny one ~3.9 GB; measured), else tiny, else the CPU. If a model you chose does not fit, it runs on the CPU (slow) and the status says so; if the GPU runs out of memory during a run, ST-ROTO continues on the CPU. `sam2.1-hiera-large` was clearly more accurate than the default `tiny` on real footage (mean IoU 0.736 vs 0.683 over 51 tests, mostly because it loses the object less often) and about 1.4× slower; use it for difficult shots. If an object splits into pieces (e.g. cut by something passing in front), each extra piece becomes a part shape (`hero_part2`), invisible on frames where it does not exist.
8. The result is one native, animated Roto shape per object inside the ST_Roto node (`hero_st…`), editable like any Roto shape, and recorded in the project file with AI provenance.
8. **Only part of the shot / frames to leave alone:** set *re-track range* to *from-to* and the frames: re-tracks then change only those frames, joining the keys around them. **exclude frames** (e.g. `12-14, 30`): the AI never processes or changes them (flashes, cuts, frames you roto by hand). **Lock range**: the named object's keys on *from*..*to* are kept exactly and guide later re-tracks (**Unlock range** to release).
8. **Hard objects:** set *re-track model* to `sam2.1-hiera-large` (or *auto*) and press **Re-track flagged**: only objects whose status says *REVIEW lost …* are re-tracked, with the more accurate model (measured: 6 lost frames -> 0 on the test shot). Track everything with the fast tiny model first.
8. Fix a frame by editing the shape in the Roto node (or draw a shape by hand), then **Re-track object** (the named object) or **Re-track all** (every unlocked object, one pass). Your keys are kept exactly; AI fills the other frames forward and backward from them.
   **Quicker fix without drawing — Re-prompt here:** go to a frame the review flags list (or that looks wrong), drag the **box** around the object on that frame and press **Re-prompt here** (tick **with point** to also use the point handle as an include click). The named object is re-tracked in both directions with that box as an extra guide; the fix is kept for later re-tracks and the whole re-prompt is one undo step. A frame that already has your own key is guided by that key: edit the key instead.
9. The status ends with **REVIEW lost …** (object missing: fix these) or **check …** (uncertain: glance) where the AI was unsure.
10. **Mattes:** *matte size*: **full resolution** or **fit 1920x1080** (default in Nuke Non-commercial; full resolution is the default in other editions) (computed at full resolution, then area-averaged to fit 1920x1080; 3-11x smaller files, same accuracy measured; HD plates are never scaled). Choose *edges*: guided filter (no AI), **ViTMatte-S** (optional learned matting, better on hair and slightly inaccurate shapes; install with `tools/models/download_models.py vitmatte-small-composition-1k` then `tools/models/export_vitmatte_onnx.py`; its weights are Apache-2.0 but were trained on Adobe's Composition-1k data — check that suits your use) or hard. Older notes: set *soft edges* (on: a narrow band around each edge is refined against the plate, no AI model; off: hard mattes identical to the shapes), then **Render mattes (EXR)**. One EXR per frame in `<project>_mattes/<shot>/` (or *matte folder*): a layer per object (`hero.alpha` in Nuke) and all objects combined in `rgba.alpha`.
11. **Matte extras** (mattes only, shapes unchanged): *RGB in mattes* **premultiplied** (plate × alpha, ready to merge over) or **straight** (plate colour, edges not decontaminated) - the EXR header records which; *edge offset* grows (+) or shrinks (−) the mattes in pixels; *edge blur* feathers them; *core/edge width* adds `core_matte` and `edge_matte` layers. If the previous mattes are open in a Nuke Read node, Windows will not let them be replaced: the new render goes to a new folder (`…_v002`) and the status says so.
11. **Holdouts and garbage mattes:** set *object name*, choose *object role* (**holdout**: cut out of the combined matte, e.g. a pole in front of the actor; **garbage**: the combined matte is kept only inside it) and press **Set role** (also in the Objects pane: **Role…**). The node's render and the EXR combined `rgba.alpha` follow it; each object's own layer stays unchanged. **Merge into…** (Objects pane) moves an object's shapes into another object (one undo step).
11. **Feather:** set a shape's feather in the Roto node as usual; ST-ROTO records it (undoable) and keeps it. EXR mattes approximate Nuke's feather (exact in Nuke's own render). **Copy shapes to RotoPaint** creates a RotoPaint node with native copies of every shape.
12. **Export shapes (JSON + SVG)** writes `<project>_export/<shot>/`: a JSON file with every object, key and its provenance (re-importable with **Import shapes (JSON)**, also into another project) and one SVG per keyed frame.
12. **Motion blur:** set *motion blur* to `global` (and *samples*, *shutter*) to have Nuke blur the shapes along their tracked motion.
13. **Back up now** snapshots the project into `<project>_backups/`. Automatic backups also run every 5 minutes while you work (only after changes) and when Nuke exits. If Nuke crashed or the project file is damaged, the status line says so the next time the project is opened; a damaged file is kept (`.damaged.<time>`) and the newest good backup is restored.
14. **Package project** writes a portable zip (project, mattes, exports, checksummed manifest; no model weights) next to the project. It includes your saved Nuke script. On the other machine use **ST-ROTO › Unpack project package…** (main menu): checksums are verified, plates that are not found are asked for (any frame of them), and every plate is checked against a fingerprint of the original footage, so the same plates in a new place are accepted and different footage with the same names is refused. Opening the unpacked script relinks its Read and ST_Roto nodes.
14b. **Delivery package**: a zip for handing over the shot - the latest mattes and shape export, the node's settings, the models used (licence, approval), processing / provenance / quality reports and a checksummed manifest. Render mattes and Export shapes first.
15. **ST-ROTO Models** pane (Windows › Custom): every installed model with licence, approval and source; **Verify** (checksums), **Self-test** (accuracy and speed on this machine), **Remove…**, **Import…** (approved models only). Models can also live in a user or studio folder: set `ST_ROTO_MODELS_USER` / `ST_ROTO_MODELS_STUDIO`; a model there is used instead of the built-in copy.
15. **System report** (node button, or main menu ST-ROTO › System report…): what this machine and Nuke edition can do - GPU and memory, AI runtime and models, the edition's limits (render size, node budget, plug-ins) - and why any feature is limited or unavailable. Include it when reporting a problem.
16. **ST-ROTO Objects** pane - its **timeline** shows each object across the shot: orange = your keys, grey = AI keys, blue = locked frames, red/yellow marks = REVIEW lost / check; click to jump to that frame and select the object.
    The pane: press *Use selected ST_Roto node* (with the node selected) to list objects; rename, lock/unlock, delete, undo, redo. **Working with others (prototype):** *held by* shows who leases each object; **Take** / **Release** a lease (only the holder can change a leased object); a supervisor can **Override** someone idle or offline for 15 minutes (recorded with evidence); **Set up signing key** creates your private key in `%USERPROFILE%\.st_roto\keys` (never in the project) so your changes are signed; **Set role…**: the first role must be you as admin. Sharing a project between machines is not in the UI yet.

## Things to know

- Shapes you edit directly in the Roto node are **never** overwritten or removed by ST-ROTO; such a shape is reported as "NOT updated (edited in Roto)". **Save Roto edits to project** (or any Track / Re-track) records your edits in the project, undoably.
- **AI input colour** (default *auto*) follows the script: Nuke's default linear sRGB, or with OCIO colour management (e.g. ACES) the working space converted through the script's OCIO config. Choose a space explicitly if your plates are, for example, already display-encoded. The choice is recorded with every AI result.
- **Formats and large plates:** any format Nuke reads works (measured: PNG/TIFF 16-bit, EXR half/float, DPX 10-bit, anamorphic pixel aspect). Nuke Non-commercial renders at most 1920x1080; for larger plates (2K, 4K, 8K, vertical) ST-ROTO lets the AI see frames reduced to fit and keeps the shapes at full resolution (status says so; measured IoU at 4K/8K equal to HD).
- **Without AI:** tick **disable AI (traditional roto only)** on the node (or set the environment variable `ST_ROTO_AI=off` for a whole Nuke session) and the AI controls disappear. Draw and edit shapes in the node's Roto, press **Save Roto edits to project**, and use mattes (guided filter or hard), export, RotoPaint copy, backups and packages as usual. This also works on a machine without the AI runtime installed.
- **Difficult sequences:** frames Nuke cannot read (missing files, gaps) are skipped and listed in the status (no key there; Roto interpolates; mattes get hard edges there). Frames of another resolution, and every frame in proxy mode, are fitted to the shot format like a default Reformat and listed; for mixed-resolution plates put a Reformat to the shot format above ST_Roto so plate and shapes line up. Proxy mode tracks on the proxy images (slightly less accurate: IoU 0.990 vs 0.995 measured); turn proxy off for final tracking. Start frames other than 0/1, negative frames, held (duplicate) frames and retimes upstream work as they are.
- **Offline:** ST-ROTO itself never uses the network (no telemetry; ONNX Runtime's Windows telemetry is switched off; measured, T-085). Nuke 17.1 Non-commercial itself contacts a server over HTTPS each time it starts; that is Nuke's behaviour, not ST-ROTO's, and it is not needed: with Nuke blocked by a firewall, Nuke and ST-ROTO work normally (measured, T-087).
- **Stereo (several views):** with the script set up for stereo (Project Settings › Views, e.g. a Read with `%V`), place your prompts in the **prompt view** (empty = the hero view, else the first view), tick **track every view (stereo)** and press **Track**. Each object is tracked in every view on that view's own pixels: ST-ROTO finds the object in the other view on the prompt frame (disparity search; the status says e.g. *found at disparity −30.0 px*) and prompts it there with a box + your clicks. You get one object per view (`hero_left`, `hero_right`); each Roto shape is shown only in its own view, re-tracks use that view, and **Render mattes** writes one sequence per view (`<matte folder>/left/`, `/right/`). The status and the Objects pane add **check** flags where the views disagree (vertical offset, size, a disparity jump, object in one view only; thresholds are provisional, tested on a synthetic stereo shot). Without the tick, Track works in the prompt view only and those shapes show only in that view. After Cancel, a failure or a crash, **Resume track** continues a stereo Track where it stopped (the status says which view and frame); finished views are kept.
- **Cameras (non-rectified stereo, multi-camera):** if the views come from cameras that are toed-in, rolled, vertically offset or have other lenses, name their camera nodes in *cameras* (e.g. `left=CamL, right=CamR`, or `A=CamA, B=CamB, C=CamC` for more views; one name if a single camera node is split per view). Track every view then finds each object along its epipolar line, at the size the depth implies (measured on a synthetic three-camera rig: found on 31 of 32 view-frames, where the plain stereo search found 0), and flags frames whose shape is off its epipolar line; **Check views (cameras)** re-checks after you edit shapes.
- **Extra channels (CG plates and other multi-layer EXRs):** every layer of the input (depth, motion vectors, normals, position, Cryptomatte, …) passes through the ST_Roto node unchanged; only alpha is replaced by the shapes (*replace input alpha*, on for nodes made from this version on; older nodes add the shapes over the input's alpha, which on plates that already have alpha is white almost everywhere: recreate those nodes). **List channels** shows the input's layers and Cryptomatte names. **Prompt from Cryptomatte:** set *prompt from* to *Cryptomatte*, *source* to the name(s) (comma separated), press **Use as prompt** on a frame, then Track. **Check with channels:** fill what your plate has - *medians of* (e.g. `depth.Z`, also normals / position / any channel), *motion vectors* (forward layer, e.g. `forward`) and *backward* (strongly recommended: without it, occlusions raise flags), *Cryptomatte objects* (filled when you prompt from Cryptomatte) - and press the button: frames where a shape jumps in depth, does not follow the vectors, or differs from its Cryptomatte matte get **check** flags (status, Objects pane, timeline). The vectors' sign convention is measured on the plate and reported. The check works with AI disabled too. Tested on a synthetic CG shot only; thresholds are provisional.
- **Review in the viewer:** press **Show shapes in viewer**: the node's shapes are drawn in the viewer, MAGENTA on frames flagged *lost*, YELLOW on *check* frames, Nuke's usual red elsewhere (untick *review colours on shapes* to keep Nuke's colours). *this frame* on the node lists the flags of the frame the viewer shows and why. (Nuke Non-commercial cannot draw custom graphics or text in the viewer from Python, so this uses the shapes' own outlines.)
- **Presets:** choose a *preset* and press **Apply** (built-in: *Quick look*, *Final quality*, *Traditional roto (AI off)*, *CG plate with passes*, *Stereo*); type a name in *new preset* and press **Save settings as** to keep your own (in `%USERPROFILE%\.st_roto\presets`); **Delete** removes your own. A studio can share presets in a folder named by the environment variable `ST_ROTO_PRESET_DIR`. Presets hold settings only - never prompts, objects, frame ranges or paths.
- **More ST-ROTO nodes** (Nodes › ST-ROTO, best made with your ST_Roto node selected - they take over its project and shot): **ST_RotoMatte** renders ST-ROTO's mattes for the *objects* you name (empty = all) and/or a *roles* filter (e.g. *holdout* for a holdout matte), with its own edge settings, and outputs them in the node graph: alpha = the combined matte, one layer per object (view them in the viewer's layer menu); the plate's RGB and other channels pass through unchanged; until you press **Render mattes** it passes its input through. **ST_RotoOutput** holds Export shapes, Delivery package, Package project and Back up for a shot. Both have **Check** (lists the project's shots and objects). They read the project as it is: press *Save Roto edits to project* on the ST_Roto node first if you edited shapes by hand.
- **Alembic:** **Export Alembic** (ST_Roto, or ST_RotoOutput) writes `<project>_export/<shot>/<shot>.abc` for 3D packages: per shape an animated closed Bezier curve (the exact spline) and an outline mesh (Nuke 17 reads Alembic meshes but not curves - load it with GeoImport). Coordinates are Nuke's Roto pixels: x right, y up, origin bottom-left, z = 0; one sample per keyed frame at the script's fps. Needs a Nuke with USD (14 or newer).
- **Model versions:** in the **ST-ROTO Models** pane, select a model: the lower table lists its versions (USED / kept). Importing a model over an installed one keeps the old one. **Use this version** checks every file of the selected version and switches to it; **Roll back** returns to the version used before; **Compare (self-test all)** tests every version on this machine without switching; **Remove version...** deletes a kept version.
- **Clean edge colours:** set *RGB in mattes* to **premultiplied, decontaminated** (or straight, decontaminated): the colour of soft edges (hair, motion blur) no longer carries the old background (measured on synthetic scenes: edge fringe 42x lower over a green screen, about 3x over a busy background; a matte that is too big reduces the gain). *spill* **auto / green / blue** removes screen spill from the foreground colour (also from genuinely green / blue foreground parts - check them). Alpha is never changed by either.
- **Chattering edges:** if an object's outline jitters from frame to frame, set *frames* (2 = 5-frame window) and press **Reduce chatter** (or **Reduce chatter (all)**): each point's path is smoothed on AI frames; your own keys and locked frames stay exactly as they are. One undo step. Use it only where you see chatter: on an already steady, fast-moving track it can round real motion slightly (measured).
- **Roto from render passes (no AI needed):** **Shapes from Cryptomatte** makes the object named in *object name* from the Cryptomatte name(s) in *source* on every frame (native animated shapes; measured IoU 0.998 vs truth on a CG shot). **Propagate along vectors**: draw the object on a frame (Save Roto edits to project), stay on that frame, choose forward / backward / both and press the button: the shape follows the plate's motion vectors (*motion vectors* / *backward* layers) until the shot ends or your next own key; something passing in front does not drag it along. It drifts slowly (measured ~0.002 IoU per frame), so add a key every 10-20 frames - propagation stops at your keys. Both are one undo step and marked "imported" (not AI).
- If you see "Nuke returned no node … 10 nodes per session", save, reopen the script and try again (Non-commercial limit).
- Report problems with the status text and the Script Editor output.
